# GodotSynth

A GDExtension (C++, godot-cpp) that adds a modular synthesizer to Godot 4.7+ (built against the 4.7 API): an engine for virtual analog, chord and future synths, modulation sources, modulated effects, and a GDScript editor addon. It's a public MIT project (github.com/EclipsingLines/GodotSynth). It's in beta, currently v0.96. See README.md for the user-facing API and CHANGELOG.md for releases.

## Build

- **Local Windows build (verified 2026-10-27):** run `python -m SCons target=template_debug -j8` from **PowerShell or cmd**, at the repo root. SCons finds MSVC on its own (VS 2022 Build Tools are installed), so there's no need for a VS dev prompt.
  - **From the Bash tool (verified 2026-11-09):** a plain run under Git Bash fails because MSYS's tools and `MSYSTEM` confuse SCons's MSVC detection. Strip the MSYS entries from PATH and unset `MSYSTEM`/`SHELL`:
    ```
    cd /c/GIT/Synth/GodotSynth && CLEAN=$(echo "$PATH" | tr ':' '\n' | grep -v -E '^/(usr/|bin|mingw64|clangarm64|ucrt64)' | grep -v -i '/Git/' | paste -sd:); env -u MSYSTEM -u SHELL PATH="$CLEAN" /c/Python314/python -m SCons target=template_debug -j8 > build.log 2>&1
    ```
    Write the log to a scratch directory, not the repo.
  - SCons is pinned to **4.11.1** everywhere (CI's `.github/actions/base-deps` and local). Install it per user with `python -m pip install --user scons==4.11.1`. Its `scons.exe` is not on PATH, so use `python -m SCons`. If you change the pin, change it in base-deps, here and in the README's "Building from source" section together.
  - A clean build compiles all of godot-cpp first, which takes several minutes, so run it in the background. Later builds are incremental.
- Use `target=template_release` for release. The VS Code `build` task runs plain `scons`. CI is a single workflow, `.github/workflows/build.yml` (a platform × debug/release matrix; artifacts are named `godot-synth-<identifier>-<target>` and merged into the release zip on tags). It installs SCons 4.11.1 via `.github/actions/base-deps` and builds Windows natively with MSVC on `windows-latest` (like godot-cpp-template; no MinGW). The build step runs `python -m SCons` under `shell: sh`, which is Git Bash on the Windows runner and works there.
- SConstruct collects every `.cpp` under `src/synth/` recursively (`os.walk`; SCons `Glob` treats `**` as `*`), so new files need no build-script edits. It aborts if it finds no sources, and CI's "Verify Library" step fails any library under 200 KB or without `synth_library_init` (#20).
- Output goes to `godot_synth/bin/` and is installed into `project/addons/godot_synth/bin/`. On Windows the output is `libgodot_synth.windows.{debug|release}.x86_64.dll`, and its name must match `project/addons/godot_synth/godot_synth.gdextension` (entry symbol `synth_library_init`). Godot must be closed or the DLL is locked.
- `godot-cpp/` is a git submodule (github.com/godotengine/godot-cpp), pinned to `10.0.0-stable`. godot-cpp is now versioned independently of Godot and v10 supports Godot 4.3–4.7; the target engine API is picked with `api_version`. `SConstruct` passes `"api_version": "4.7"` to `SConscript("godot-cpp/SConstruct", ...)` (the way godot-cpp's README documents), and `api_version=4.x` on the command line overrides it. A build that targets 4.7 won't load in older Godot. After cloning, run `git submodule update --init`. To change versions, `git -C godot-cpp fetch --tags origin`, `git -C godot-cpp checkout <tag>` and then `git add godot-cpp`. A clean build takes about 7 minutes locally, most of it compiling godot-cpp.
- No binaries are committed: `bin/` (including `project/addons/godot_synth/bin/`) is gitignored, so a fresh clone has no DLL until you build. The GitHub release zips (v0.93–v0.95.1) contain full 1–2.7 MB libraries. The 3–16 KB stubs that some old local checkouts have came from a CI run on 2025-03-13 whose SConstruct globbed `src/*.cpp` and compiled zero sources (issue #20). Don't trust those.
- `src/gen/doc_data.gen.cpp` is generated by SConstruct (`GodotCPPDocData`, `editor`/`template_debug` only) from `doc_classes/*.xml`. That folder doesn't exist yet, so the file registers an empty class reference. `src/gen/` is gitignored; don't commit it.
- Known pitfall: `LNK4042` on `src/gen/doc_data.gen.*.obj` (the object is specified twice) is treated as an error. Clean the stale `.obj` before relinking.
- **Tests:** `tests/offline_render.gd` is a headless regression test. It renders notes with `SynthOfflineRenderer` (no audio device) and checks length, pitch at 44.1 and 48 kHz, levels, waveform selection, sub square, super saw, release silence, determinism, PolyBLEP aliasing, the master chain (stereo ping-pong, reverb stability) and `PitchHelper`. Build the debug DLL first, then run from the repo root:
  ```
  C:\Godot\4.7\Godot_v4.7-stable_win64_console.exe --headless --path project -s ../tests/offline_render.gd
  ```
  It prints `PASS`/`FAIL` per check and exits 0 only if every check passes. Add a check there for every audio bug you fix. CI runs it in the Linux debug job ("Offline Render Test"): it downloads Godot 4.7 from `godotengine/godot-builds`, checks its SHA-512, runs `--import` once (a fresh checkout has no `.godot/extension_list.cfg`, so the extension wouldn't load) and then the script. When you raise the Godot version, update `GODOT_VERSION` there too.
- `-s` scripts only run in a build with the script runner, so they work with the editor/debug binaries but not in an exported release build. Test from the editor binary.
- For a hands-on check, open `project/` in Godot and play `addons/godot_synth/keyboard/piano_keyboard.tscn`. `project/issue_1.gd` is a repro scene script.
- Godot 4.7 is installed at `C:\Godot\4.7\` (`Godot_v4.7-stable_win64.exe`, plus `Godot_v4.7-stable_win64_console.exe` for headless runs). For scripted checks, use `C:\Godot\4.7\Godot_v4.7-stable_win64_console.exe --headless --path project --editor --quit`. Close Godot before building, because it locks the DLL.

## Layout

- `src/synth/register_types.cpp`: every class must be registered here (`GDREGISTER_CLASS` or `GDREGISTER_ABSTRACT_CLASS`), grouped into `register_*()` helpers. Reverb is registered for use in `master_effect_chain`; per voice it is expensive.
- `src/synth/core/`: `AudioSynthPlayer` (node, voice allocation), `SynthNoteContext` (per-note handle: note_on/off, velocity, articulation), `SynthVoice`, `SynthConfiguration` (abstract) plus `ConfigurationPrototype`/`SynthPreset`, `AudioStreamGeneratorEngine` (abstract oscillator engine) plus `EngineFactory`, `ModulatedParameter`/`ModulationSource`, `WaveHelperCache`, `PitchHelper`, and the stream/playback classes.
- `src/synth/va/` is the virtual analog engine (the shipped one). `src/synth/chord/` is the chord engine (work in progress).
- `src/synth/mod/`: modulation sources (adsr, lfo, velocity, keyboard tracking, note duration, articulation).
- `src/synth/effects/`: `SynthAudioEffect` base, `EffectChain`, and the `filter/`, `delay/`, `distortion/` and `spatial/` effects.
- `src/synth/time/`: `BpmManager`, `Sequencer`.
- `src/synth/ext/`: vendored third-party headers (`qoa.h`). Don't reformat them.
- `project/addons/godot_synth/`: the editor plugin (`synth_plugin.gd`), custom inspectors (ADSR/LFO/modulated-parameter editors), the `keyboard/` test scene, the `music_engine/` GDScript helpers (arpeggio, motif, rhythms), and the `.tres` presets in `assets/`.
- `docs/` is the Jekyll GitHub Pages site (eclipsinglines.github.io/GodotSynth). Anything added there is published.
- `design/` holds internal design notes that are not published: the QOA/preload plan migrated from cline. `custom_inspector_implementation.md` at the root is an older design note.

## Headless checks in Godot 4.7

Use the console exe (`C:\Godot\4.7\Godot_v4.7-stable_win64_console.exe`), which prints to stdout. Build the DLL first. Run these from the repo root:
- Parse-check one script: `--headless --path project --check-only --script res://addons/godot_synth/<file>.gd`. Exit code 0 means it parsed.
- Scripted run: `--headless --audio-driver Dummy --path project -s <path\to\script.gd>`, where the script `extends SceneTree`. Keep it in the scratchpad, not in `project/`. For a smoke test, load `res://addons/godot_synth/keyboard/piano_keyboard.tscn`, add it to `root`, and call `play_note`/`stop_note` on its `CenterContainer` node (the `SynthPlayer` script) for a few frames. Then return `true` from `_process` to quit. Don't let a script error loop forever, because it floods stdout.
- Add `--verbose` to see which addon scripts and resources load and to get details on leaked instances.
- Known noise: the editor prints about 148 `Instantiated ModulatedParameter used as default value for <Effect>'s "<x>_parameter" property` warnings.
- A `-s` script that calls `ResourceSaver.save` drops the `uid=` fields from `.tscn`/`.tres` files, so resave scenes in the real editor instead.

## Conventions

- Format with the repo's `.clang-format`: LLVM base, **tabs**, indent width 4, no column limit.
- Source files use **LF** line endings (the index and working tree are both LF, and there's no `.gitattributes`). Keep them LF when editing.
- Headers use `#ifndef NAME_H` include guards. Everything goes in `namespace godot { … }`. Classes use `GDCLASS(Name, Base)` with `static void _bind_methods()` in `protected:`. Parameters are prefixed `p_`, and there are `set_x`/`get_x` pairs exposed with `ClassDB::bind_method(D_METHOD(...))` plus `ADD_PROPERTY`.
- Modulation sources implement `get_value(const Ref<SynthNoteContext>&) const`, `reset()` and `duplicate()`.
- Effect parameters should be `ModulatedParameter`s so they can take modulation.
- Audio-thread code must not allocate or lock in the per-sample path. How the hot path stays allocation-free:
  - `SynthAudioStreamPlayback::_mix` mixes in 512-frame chunks into fixed buffers: each voice's `SynthVoice::render()` → `AudioStreamGeneratorEngine::render()` writes into a raw float buffer, then `SynthMasterBus` runs the optional `master_effect_chain` on the stereo mix. `process_block()` still exists (it allocates) for the offline renderer and engines without a `render()` override (the chord engine).
  - Effects look parameters up with `get_parameter(PARAM_X)`, where `PARAM_X` is a `static const char*`. That hits a per-effect pointer-keyed cache (`param_cache`), so keep passing the constant, not a built `String`. `VAOscillatorEngine` keeps raw `ModulatedParameter*` members, set in `set_parameter()`.
  - First lookups and buffer setup allocate, so engines and master chains are warmed up on the main thread (one silent sample, then `reset()`) in `set_effect_chain()` and `SynthMasterBus::prepare_chain()`.
  - A new master chain is prepared on the main thread and handed over with the `SET_MASTER_CHAIN` event. The audio thread swaps the old chain into the event slot, so it is freed on the main thread when that slot is next used.
  - `EffectChain::prepare_stereo()` duplicates non-stereo effects for the right channel; call it off the audio thread. `reset()` must not rebuild anything.
- Update CHANGELOG.md (Keep a Changelog format) for user-visible changes.
